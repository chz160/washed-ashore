## Answers per question
1. Reflections. Planar: doubles scene draws because a second camera re-renders the scene (ruled out anyway). URP SSR: official version is preview-only in 6.7 alpha, so not usable on a stable Unity 6.x as of this run (confirm project Unity version); no ms, no WebGL statement. Shader-local SSR raymarch: no sourced cost found. Reflection probes (baked/realtime/box projection) and plain sky/fresnel: no ms found; the SSR post confirms probes/skybox as the fallback cubemap path. Unverified belief: sampling a baked probe or sky cubemap is near-free next to a raymarch; no measurement retrieved.
2. Depth/opaque copies. Unity says enable only when a shader needs them (water refraction and depth fade do). Mobile/tiled GPUs pay GMEM load/bandwidth. Staggart says depth via prepass doubles geometry draws; URP can instead copy depth after opaques (Depth Texture Mode option, per search summary). No desktop 1080p or WebGL ms found. On WebGL2 (GLES) non-MSAA depth copy works; avoid MSAA on web.
3. Mesh strategy. No sourced cost comparison. Crest (LOD rings) is draw-call heavy; knobs are LOD count and Min Scale. Staggart: cost depends on vertex count and screen pixels; waves run per vertex and per pixel. GPU Resident Drawer unavailable on WebGL; SRP Batcher works on WebGL2 (per-tile quads sharing one material batching fine is an unverified inference). Frustum culling of per-tile quads: standard Unity behaviour, no source retrieved.
4. Distant LOD. Only evidence: Staggart "Simple" shading mode for low-end and "less screen coverage = cheaper". Normal fade/fog blend/horizon practice: not evidenced.
5. WebGL2. Evidence: stripping settings, DXT-desktop / ASTC-mobile split, prewarming, no GRD, non-MSAA depth copy only. No measured browser FPS for transparent full-screen surfaces; no per-variant build-size numbers.
6. Per-feature cost tables. Crest and Staggart docs have none (qualitative ranking only). KWS docs and Unity forum profiling threads not reached.
