## Answers
1. Passes: Depth Texture on gives cameraDepthTexture via CopyDepth (After Opaques / After Transparents) or a DepthPrepass (Force Prepass; also when depth priming needs one). Opaque Texture on gives a CopyColor pass producing cameraOpaqueTexture. Opaque Downsampling text and the exact rule for prepass-vs-copy beyond the Depth Texture Mode setting were NOT retrieved. WebGL/GLES notes found: Native RenderPass has no effect on GLES; depth priming not with MSAA. No explicit WebGL2 statement for CopyDepth in retrieved pages.
2. CopyDepth on WebGL2 with MSAA off/on: NOT evidenced this run. Only an old (URP 10) WebGL black-scene-with-Depth-Texture issue (low confidence) and an MSAA+OpenGL camera-stacking black-screen title. Needs a real WebGL2 build test on 6000.6 (Force Prepass vs After Opaques, MSAA 1x vs 4x).
3. Measured ms numbers: none found. Unity docs are qualitative only (bandwidth, GMEM loads, MSAA store/load). Desktop DX11/12 cost of a full-res copy being small is an unverified belief.
4. Scene Depth disabled gives 0.5 grey (water would show constant mid depth, no error); Scene Color disabled gives black. Both URP/HDRP only; use a Transparent surface. Settings are per URP asset (quality level), so the WebGL quality tier asset must have them enabled.
5. Baked alternative: Crest depth cache (top-down ortho heightfield, baked or realtime). Pros: no per-frame cost, independent of camera depth/MSAA/platform copy support, view-angle independent. Cons: static only (baked), setup and resolution limits, edge transitions must be authored, cannot see dynamic objects. Staggart docs not retrieved.
