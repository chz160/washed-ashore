## Answers (Q1)

(a) Custom ScriptableRendererFeature/ScriptableRenderPass? NO. Nothing in the tree, and the only runtime C# that touches rendering (PlanarReflectionManager) has no pass/feature types. So the RecordRenderGraph-vs-Execute question does not arise for the water itself. The only render-pipeline API used is `RenderPipeline.SubmitRenderRequest(camera, UniversalRenderPipeline.SingleCameraRequest)`, a supported public API. (Doc note: the URP asset's Depth/Opaque texture options are used instead of a custom copy pass.)

(b) Yes, the local planar reflection is a SECOND CAMERA render (SubmitRenderRequest of `_reflectionCamera`, render-scale controlled, layer-mask filtered). It can be disabled with certainty at two levels: per-material toggle `EnablePlanerReflection` (shader_feature_local `_ENABLEPLANERREFLECTION`, strip-able), and by simply not placing a PlanarReflectionVolume in the scene (manager returns early when no active volume). Reflection then falls back to reflection probes / cubemap (`SampleReflectionProbe`, `CubeMap.hlsl` subgraphs exist). Caveat: I did not see the exact default value of the toggle in template materials (not read).

(c) Camera Depth Texture: REQUIRED always (docs say water can be invisible without it). Opaque Texture: only when Refraction is enabled (`_ENABLEREFRACTION`). So disabling refraction removes the Opaque Texture dependency.

(d) Wave displacement is a closed-form Gerstner (two waves) from world XZ position and time, trivially mirror-able in C#: k=2*pi/L; omega*t = sqrt(9.8*k)*t*speed; phase = k*dot(dir_n, p.xz) - omega*t; y = H*cos(phase); horizontal = -dir_n * (Sharpness/k)*sin(phase) (the Sharpness/(k*H)*H cancels). Two things matter for reproduction: (1) it is a vertex displacement, so the true surface height at (x,z) requires inverting the horizontal term (a couple of fixed-point iterations) unless you accept the Gerstner small-steepness approximation; (2) `TimeParameters.x` is the shader time; [unverified belief from training: ShaderGraph `_TimeParameters.x` = `_Time.y` = seconds since level load; not verified this run] so a C# mirror must use the same clock origin (Shader time vs Time.timeSinceLevelLoad) or drive time from a material property. There is NO existing C# height query or buoyancy script, and the maintainer confirmed there is none (issue #11). Whether the two waves are summed (vs one overriding) I did not confirm; summation is by far the likely reading but unread.

(e) Compute shaders: none. Nothing in the tree or in grep of the shader/C#. A caveat for WebGL2: the shader declares `#pragma target 4.5` in one pass (L6714; deferred-style pass by the keyword set, not verified). WebGL2 builds use GLES3, which Unity treats as shader model ~3.5 equivalent; SM4.5 pass should be skipped or stripped when not in Deferred, but not confirmed here. Also the shader is a large generated Shader Graph output (1.28 MB, ~7000 lines) with many multi_compile keywords: variant/compile-time and size risk for WebGL, unverified.

(f) WebGL: no mention in docs/issues (search total 0). Only platform-related issue is Meta Quest not rendering (maintainer had no device to test). Cadence: single maintainer, 41 commits, 33 in the last 12 months, 8 releases, three in the last ~2.5 months (v1.1.4 Aug 19, v1.1.5 Oct 1, v1.1.6 Oct 4), last push yesterday (2026-10-05), 0 open issues, 510 stars. Active but single-maintainer, hobby-project risk. Authored on 6000.0.72f1 though; compatibility with 6000.6/URP 17.6 untested in evidence.

(g) Configuration: a plain material (shader Properties) per water surface; 8 template materials and prefabs; custom material inspector in Editor/UberStylizedWaterGUI.cs. Editor scripts can set everything through `Material.SetFloat/SetVector/SetColor` and `EnableKeyword` on the `_1st_Wave_*` / `_2nd_Wave_*` names and `_ENABLEWAVE` etc. No ScriptableObject involved. Property names are exposed (e.g. `_1st_Wave_Length`, `_1st_Wave_Direction` as Vector, `_1st_Wave_Sharpness`), so a C# class could read the same material properties to evaluate the identical function, keeping shader and C# in sync from one material (this is an inference).

## Leads

- Uber source Shader Graph (`Shader/Devlopment/UberStylizedWaterGraph.shadergraph`) is the editable route if forking; the shipped `.shader` is generated and ~1.28 MB.
- To confirm before adopting: (1) build the demo in a 6000.6 URP 17.6 project for WebGL2 and read the shader compile/variant log; (2) read the `#pragma target 4.5` pass and confirm it is stripped for non-deferred; (3) read the full `shader-prop-reflection.md` / `UberStylizedWaterGUI.cs` for how `EnablePlanerReflection` defaults and whether templates (e.g. Murky) have it off; (4) check template `UWa-Template-Murky.mat` settings for the "murky slow river" look (it exists: `Water Template Murky.prefab`).
- Reuse option: Uber's Gerstner subgraph math is fully legible in the generated HLSL, so a custom water could copy the formula (verify licence of copying: MIT permits it with the notice).
- Maintainer said height query is "a suggestion for next version" (Nov 2025); v1.1.2-1.1.6 shipped since: release notes were NOT read, so whether a height API landed is not fully excluded by tree search, but no matching file exists in the current tree.
