## Answers

**Q1 Approaches and CPU reproducibility.** Sum of sines and Gerstner are closed-form functions of (x,z,t), so a CPU copy matches the shader up to float rounding (GPU Gems eq. 1, 9; claims 1-2). The shipped-package pattern is: BoatAttack replicates the Gerstner sum in a Burst job on the CPU with Time.time (claim 9); Crest does GPU compute queries with async readback, and a baked-FFT CPU path for headless servers (claims 4, 6); UE exposes CPU wave query functions on the same Gerstner asset (claim 13). Crest's FFT-derived surface is not reproduced analytically on the CPU by default; it is read back or baked, so FFT is the costly option for exact server parity. Scrolling normal maps give no displacement, so there is nothing to sample (this is inference from the definition; no source needed). Flow maps are a texture-space trick (claim 16) with no height. I did not retrieve sources on Tessendorf FFT cost, Atlas or Rust, so those are not covered.

**Q2 Gerstner horizontal displacement.** The surface point displayed at rest position p0 is (p0.x + sum Q A D cos(phi), sum A sin(phi), p0.z + ...). Height at a fixed world (x,z) therefore needs the rest point p0 with p0 + d(p0) = (x,z). Evidence: a Babylon commit uses a fixed-cap Newton inversion (claim 11, cap and error not stated); the Godot blog skips inversion and evaluates at (x,z) directly, accepting the error (claim 12); BoatAttack summary shows displacement accumulated but I could not confirm whether it is inverted (claim 9). Convergence condition (my inference, unverified): with sum Qi wi Ai <= 1 (claim 2) the displacement map is a contraction-like mapping with Jacobian near identity, so fixed-point iteration x_rest = (x,z) - d(x_rest) converges in a few steps; for a near-flat river with small steepness the direct evaluation error is of order Q A, which may already be below the accuracy target. Not evidenced with numbers. Pitfall confirmed by claim 10: never feed a displaced result back as next-frame input.

**Q3 Time sync and precision.** Network time is a server-time offset to local time (Crest claim 8, UE claim 14). Use the same time value for shader and CPU: set a global (e.g. `Shader.SetGlobalFloat`) from the same synchronized time rather than reading `_Time` in the shader, so the two cannot diverge (inference from claims 8, 14; Unity-specific global approach not source-verified). Float32 loss: wrap or `frac` the time (claim 18); a safe wrap period must be a common multiple of all wave periods (inference; or pick wave periods as integer multiples of a base period, then phase = 2pi*frac(t/T)*n exactly). Compute time in double on the CPU and send only the wrapped float to the GPU. Large world coordinates: not found in any source; standard fix (camera-relative or tile-local offsets) remains an unverified belief.

**Q4 Networking.** Pattern across Crest, UE, and Sea of Thieves: waves are a pure function of (params, seed, server time); the server sends only params and a clock offset (claims 7, 8, 14, 15). Do not use dynamic or simulated waves for multiplayer (claim 7). UE forum: physics need not be bit-exact because both ends solve the same math from synced time (claim 14); buoyant objects are still server-authoritative with normal state replication (inference). Sea of Thieves GDC talk, Rust/Atlas, Photon/Fish-Net/NGO: not retrieved.

**Q5 Buoyancy.** Evidence is thin: Godot blog uses probe nodes sampling the height function (claim 12); Crest provides per-point async queries and a Min Spatial Length LOD for sampling (claims 4, 5); BoatAttack samples a position array through a job (claim 9). Accuracy targets and voxel counts: not found.

**Q6 River flow.** Catlike's two-phase technique: uv' = uv - flow * (progress + offset), progress = frac(t + phase), weights w = 1 - |1 - 2 progress|, B offset 0.5 (claim 16). Catlike states it aims for believable appearance, not physical accuracy (claim 17). It is texture advection only; it moves no geometry, so it does not affect the height function. A physical current, if wanted, is applied in C# as velocity on floating bodies; keeping it visually consistent means choosing flow speed (UV per second times texture world scale) equal to the physical current speed. No source states this requirement; it is inference. Valve Portal 2 paper not retrieved.
