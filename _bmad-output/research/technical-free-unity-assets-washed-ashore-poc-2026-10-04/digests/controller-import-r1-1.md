## Headless import paths
- **Works GUI-free (documented):** `-batchmode -createProject <path>` (empty project); `-createProject` + `-cloneFromTemplate <template archive/dir>` to pick a template such as URP (the template's on-disk location was not found this run); `-importPackage <abs path .unitypackage>` (no dialog); `-executeMethod` for scripted setup; editing `Packages/manifest.json` for registry, git-URL and scopedRegistry (OpenUPM) packages, which resolve on the next Editor or batch launch; the URP material converter via `Converters.RunInBatchMode` + `-executeMethod`.
- **Caveats:** a `-quit` combined with scripted ImportPackage can kill the import before delayCall runs (6000.0.23f1). Prefer `EditorApplication.Exit()` from the script, or a dedicated `-importPackage` run. Batch mode cannot open a project that is already open in an Editor. Exceptions exit with code 1. Git URL packages need git on PATH. I believe this but did not verify it this run.
- **Needs GUI/login:** acquiring any Asset Store package (free included) requires a Unity ID, an "Add to My Assets" step on the web, and a Package Manager download in a signed-in Editor. No official CLI or API exists. After one manual download, the cached .unitypackage under %AppData%\Unity\Asset Store-5.x can be reused headlessly (community claim).
