**By category:** ENV 6 entries (~8 min) · CLI 14 (~11 min) · API 6 (~6 min) · AGENT 4 (~2 min) · SPEC 5 (~7 min). Entries tagged with two categories count in both, so the category minutes add up to more than the total.

**Top 3 friction points:**

1. **Live Editor vs. batch commands (CLI).** `unity test` and `unity build` each spawn their own batchmode Editor and need the project lock, so every verification cycle is close Editor → run → reopen → re-open the scene (the Editor comes back on Untitled). Together with `projects create` refusing a non-empty folder (it forced a scaffold-and-move workaround that left `productName=washed-ashore`), the project lifecycle is the CLI's weakest area. Fix candidates: run PlayMode tests through the live Editor (`unity command run_tests --detach` / `job wait`), a create-into-existing option, and restoring the last scene on reopen.
2. **Agent shell environment (ENV).** Four of six agents lost time to the Bash tool's Windows-style PATH (`ls`/`head`/`tee`/`unity` not found), about 9 min in total, plus quoting problems going from Bash into pwsh. This isn't a Unity problem, but it was the most repeated cost. Fix: one shared preamble or a wrapper script in the pod prompt.
3. **Command discovery and argument semantics (CLI) plus terrain persistence gotchas (API).** Tags were mistaken for command names, a mistaken call wrote errors to the console, a positional argument bound to the wrong parameter, a "project-relative" `save_path` landed under `Assets/`, `--project-path` means different things on `status` and `command`, `unity logs` reads the Hub log rather than the Editor's, and `eval` fails during a domain reload. Separately, TerrainData has to be saved to disk before alphamaps are written, and re-creating it wipes the heights.

**What worked well:** `eval` / `eval_file` round trips of 0.2–5 s (a 68-FBX remap and reimport in 5 s; a full world rebuild in 2 s); `unity recompile` in about 4 s; zero Safe Mode entries, zero blockers and zero assists; a PlayMode suite of 16–18 s; a first Windows build of 437 s with a correct verdict and provenance manifest. From creating the empty project to having a built exe took about 27 min of wall-clock time (22:16 to 22:43).
