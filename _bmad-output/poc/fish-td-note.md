## 1. What the fish are (as landed)

- **Virtual population.** Each 32 m cell's groups are a pure function of (seed, cell, tuning, water): `FishPlan.Cell` / `FishPlan.Sample` (Assets/Scripts/Fish/FishPlan.cs), plan version 1 (`const ClassRelocation = false`). Bands by bed depth from `TerrainQuery.TryGroundHeight`, except the open band's outer edge at 50 m of `BellsBendLevelMaps.ShoreDistance` (ruling/fish-depth-bands rev 4). Structure is a tag from f-level's anchors (`FishAnchorQuery`). The F3 census calls the same functions.
- **Live set.** Only cells within 50 m (in) / 60 m (out) of the player, measured to the cell's nearest point, are simulated; at most 2 cell plans per frame, nearest first, 1 s back-off for blocked cells; a cell goes live only where a terrain tile exists. Nothing appears or disappears while it could be seen (`FishView.CouldSee`).
- **Simulation.** `FishSimWorld` (+ .Steer, .Grid, .Events, .Render): struct arrays, no GameObject, collider or rigidbody per fish. Fixed 15 Hz tick with render interpolation; Reynolds steering with a per-fish state machine; schools are an anchor plus body-feasible slots (>= 1.5 BL apart). Every move passes `Clear()`: usable column, nose and tail over water, spacing, and no body-box overlap with any live fish (uniform-grid broad phase).
- **Depth.** Body box between bed + clearance and the moving surface (`WaterBody.SurfaceY` = WaterLevelY + `WaterMotion.Offset` at `WaterClock.Now`) minus margin; only Rise/Jump/Bask leave it.
- **Randomness.** `FishRandom`: a stateless counter hash of (runSeed, stream, cell, fish, counter). Fish identity is a stable 64-bit id from (cell, groupIndex, member).
- **Rendering.** `FishRenderer` draws bodies with `Graphics.RenderMeshInstanced` and a VAT baked from the facing-corrected Swim clip (`FishVatBake`); `FishUnderwater.shader` draws after the water with its own Beer-Lambert murk from the water material's numbers. One visibility rule (`FishMurk`, floor 0.02) shared by the sim's no-pop rule and the renderer (`FishDrawRule`); draw radius 25 m submerged, 40 m airborne jump, 3 m edge fade; at most 3 bodies shown (`FishVisibleCap`, no eviction, 1 s fade-in, 3 s cooldown). Surface signs: `FishSurfaceFx` + `FishRing.shader`, real-size footprints, 6 live, flat event radius 150 m (`FishEventDistance`).
- **Cost (slot F, Windows Editor PlayMode, ~125 live fish):** Fish.Sim median 0.14 ms; Fish.Events mean 0.035 ms, p99 <= 0.33 ms; 0 B GC per frame (EditMode allocation test).

## 2. Server authority over fish

**Ready now:**
- **The population is recomputable.** Which groups exist, where they anchor, their species, sizes and member ids are a pure function of (seed, cell, tuning, water). A server can generate the same fish for any cell without simulating, as the F3 census already does in EditMode.
- **Stable identity.** A fish's id is a hash of (cell, groupIndex, member), independent of activation history (test `FishIds_AreStable_AcrossActivationHistory`). Client and server can name the same fish.
- **No physics, no GPU.** Steering, depth clamp and Clear() read only terrain heights, LevelMaps, structure anchors and the analytic water surface. A Unity headless server runs `WashedAshore.Fish` without `WashedAshore.Fish.Rendering`.
- **Time.** The sim advances by a fixed-step counter, and the surface comes through `WaterClock`, so a server clock can drive both (water-td-note section 4).

**Gaps to close before the server is authoritative:**
1. **Trajectories are not per-cell pure.** Cross-group `Clear()` couples fish in neighbouring cells, the jump-rate cap and the live-vs-sign event choice depend on which cells are live, and the hitch cap drops sim time. So motion is a function of (seed, the player's path, the live-set history), not (seed, cell, tick). A server must simulate a whole region around each player (and the union of regions for several players), and clients must receive fish state, not just recompute it. Ambient fish far from any player can stay client-only and non-authoritative.
2. **Plan versioning.** The `FishRandom` draw counter is shared across species in a cell, so ANY tuning change reshuffles the population. Key the plan by (FishPlan.Version, FishTuning content hash) and refuse to mix versions between server and client.
3. **TerrainQuery "not loaded".** Fish already treat a missing tile as land (they never call `TerrainQuery.Height`), but the server needs the explicit not-loaded result from water-td-note follow-up 1, or a streamed-out tile will delete fish on one side only.
4. **Unity types.** FishSimWorld uses Mathf/Vector3/Quaternion. Fine for a Unity headless server; a non-Unity .NET server needs a port, checked against the EditMode suites.
5. **Float determinism.** Same as water: "same result within tolerance", not bit-identical across CPUs. For authority, the server state wins and clients correct; do not lockstep.

## 3. Hooking a specific fish

- **Addressing.** A cast or lure resolves to a fish by stable id: query live fish within reach (a spatial query on the existing broad-phase grid) and pick by id. A client's "I hooked fish X" is then verifiable: the server regenerates the cell, checks X exists, checks it is live in its own region simulation, and checks the hook point is within tolerance of X's server position at that tick.
- **What a hook needs that doesn't exist yet:**
  1. A lure/bait interest model (attraction radius, species preference), added as a new steering state (Approach, Strike) in the same state machine; it must go through `Clear()` like every other move.
  2. A visibility exception: a hooked or approaching fish must be drawable regardless of the visible-body cap and (when shallow) the V1 tier, otherwise the caught fish can't be seen. Today the cap and tiers are presentation rules for ambient fish only.
  3. The scatter rule must ignore the player's own lure (the player stands still while fishing, but the line and lure are near the fish).
- **Species that are never drawn.** V3 / neverDrawBody species (e.g. gizzard shad) have no rendered body today. Hooking one needs a hero representation (see section 4), and its sim has a known limit (section 5, stuck schoolmates).

## 4. Moving from instancing to an individual fish when caught

The ambient fish are rows in arrays drawn by instancing; a caught fish needs to become a real object (a fight, a reel-in, a held fish shown up close). Recommended hand-off:

1. **Promote.** On hook, `FishSimWorld` marks the fish `Promoted` (excluded from Tick, the cap, cell drop and group logic, but its slot stays reserved so the plan's id isn't reused). A pooled hero GameObject spawns at the fish's interpolated pose and the same yaw (rotation = `LookRotation(forward, up)`; still no rotation constants).
2. **Same look on the hand-off frame.** The hero uses the SkinnedMeshRenderer + Animator (Swim clip) of the facing-corrected prefab, or the same VAT shader through a single-instance draw. For the swap to be invisible: the same variant, tint, scale and Swim phase (the VAT row maps to normalised clip time), and the same murk composite (FishUnderwater on the hero material, with the water terms from the one `FishMurk`). The instanced draw stops on the same frame the hero starts.
3. **The fight is authoritative state.** Hero position, stamina and line tension live on the server for networked play. The hero moves by steering forces through its own depth clamp against `WaterMotion` (the F4 rule) and land/shore checks, not by physics against water (there is no water collider by design, ADR water-1).
4. **Release or keep.** On release, despawn the hero only while not drawable (the N7 rule), or swim it out beyond the draw radius first, then return the id to the sim as a dormant member (it regenerates from the seed on the next cell entry). On keep, the id is retired; record it so a re-generated cell doesn't respawn the same fish (a per-save "taken" set keyed by fish id).
5. **Above water.** A landed fish is out of the murk path (T = 1). The 5-bit oct normals in the VAT were judged fine for ambient views, but a held fish close to the camera is where they would show first: redo the VAT-vs-mesh normals comparison (deferred item 2b) before using the VAT for hero close-ups, or use the skinned mesh for heroes.
6. **Cost.** One hero at a time is negligible (one SkinnedMeshRenderer; CPU skinning on WebGL2 is fine at n = 1). Keep it to a small pool.

## 5. Known limits (as landed)

1. **V3 school members can stall.** Gizzard shad and skipjack herring (tier V3, never drawn) can hold against a schoolmate for 10-24 s (slot F: 9.7 s stuck and 10.1 s escape at seed 303 by the sim timer; an offline probe proxy from TestResults/fish-probe-f4f5-*.jsonl gives V3 runs of 9.5-24.0 s and drawable V1/V2 runs <= 2.0 s at all seeds). The 5 s stuck bar is gated on drawable tiers only (ruling/fish-stuck-bar-scope), a scope correction made after results and disclosed as such. Invisible today; relevant if V3 bodies are ever drawn or hooked. The optional fix (re-slot to the nearest free planned slot, Clear-tested) is approved but not landed.
2. **Shore distance over-reads near other dry ground.** LevelMaps.ShoreDistance is distance to the playable inner bank, so water beside the far bank or an island reads "far" (1.9% of wet cells, worst +123 m). That only removes open-band fish there; it never adds fish beyond 50 m (ruling/fish-shore-guard). Shelf/ramp fish there are depth-based and present.
3. **Canopy occlusion isn't modelled** in the F7 "seen" checks (trees occlude by trunk collider only), so F7 slightly over-counts, mostly from the bluff (ruling/fish-f7-occlusion). The earlier "false occlusion" behind the terrain-only proposal was never reproduced.
4. **Instant visibility steps** remain only where a body is already near invisible: the murk floor (alpha ~0.02), the frustum, and the V1 0.6 m tier step (up to ~0.2 alpha in one frame, looking straight down). Range edges fade over 3 m. If F8 shows the tier step, add a 0.5-0.6 m alpha ramp in `FishDrawRule.Decide`.
5. **Jump re-entry.** A jumping fish leaves the visible-body cap; on re-entry it waits out the 3 s cooldown before fading back in. The splash masks it.
6. **Population drops on tuning edits.** Any FishTuning change reshuffles the plan (section 2.2).
7. **F3 per-seed noise.** The plan is unbiased (class-level within 0.4%, band totals within 0.15%, per species x band z-scores mean +0.26, sd 0.86). Per-seed ±25% at 10-70 groups is noise-limited; the grading rule is f-qa's.
8. **Water surface for fish is the flat level if no WaterBody is active.** That's a scene-setup fallback, not a runtime path in World.unity.
9. **Pre-existing, not fish:** BirdsCostAtMostTenPercentFps and WildlifeCostsAtMostTenPercentFps already failed on 2026-10-06, before fish landed (TestResults/qa2-s4-perf.xml, bb-tq-performance.xml, bb-qa7-performance.xml). Owner: the birds/wildlife code, outside this pod.
10. **F10 W1 regression from new fish test code, fixed in #26 (test-only); W1 passes in TestResults/fish/slot26-editmode.xml (105/105).** Water W1_NoLiteralWaterHeight flagged the literal 1.61f (MapConfig.WaterLevelY) in Assets/Tests/EditMode/FishRendering/FishSignShapeTests.cs:47 and :102 (TestResults/fish-qa/ab/ab-grade.txt); the value was arbitrary in both tests.
11. **Full-suite wildlife seed 303 = 185** (#25): attributed to the pre-existing W-QA-1 test-order dependence, exposed by the larger suite; not seen in any filtered run, fish-off included. A full-suite fish-off run was not performed, so the attribution is by pattern, not proof. Owner: wildlife.
12. **Fish rendering on WebGL2 is unverified.** The VAT is RGBA16F, and Unity WebGL2 sampling of RGBA16F in a vertex shader was never confirmed (td-item-5-technique.md 5.2); no web capture was taken. If it fails, fish draw collapsed or invisible on web while counters and FPS look normal. Fallback: one bake setting, FishVatBake.Rgba32 (positions quantised to the clip box plus an RGBA32 oct-normal texture), already implemented (the shader branches on _VatInfo.z) but never exercised in a shipped build.
13. **Web FPS with water and fish in view not measured** (Noah's direction); the water pod's web gap stays open.

## 6. Incidents and lessons from this pod

- **Signs never rendered** until slot #17: `FishSurfaceFx.set` was null in World.unity because the scene setup tool wired only `FishRenderer`. All earlier F7 sign counts measured raised, not drawn, signs. Guards now: missing references = error + disable; a scene-wiring test over every fish component's references; F7 asserts an issued draw for counted signs (incident/fish-signs-not-rendered).
- **Measurement tools can lie.** The look-dev stills projected into the 640x480 batchmode screen instead of the 1920x1080 target; `WaitForEndOfFrame` never fires in batchmode. Per-shot twin gates caught both (lesson/offscreen-projection-batchmode, lesson/batchmode-waitforendofframe).
- **A test that recomputes the thing it grades will drift.** The census double-counted structure area until it was made to call `FishPlan.Sample`. Graders must call the shared function.
- **Exact bounds beat sampled checks.** The slot-spacing proof (clip boxes sit 0.125-0.165 BL behind the pivot) moved the school spacing from 1.2 to 1.5 BL; sampling at two yaws had passed 1.2.

## 8. Pod results that bear on fishing

- **F7 (re-graded with drawn signs and the flat event radius, slot F):** FINAL FAIL per f-qa (TestResults/fish-qa/f-grade.txt; TestResults/fish/slotF-playmode-final.xml). Shore walks: 7.3 / 15.0 / 11.0 body sightings per minute; 0 legible surface events; bluff looks under 1.2 per minute at all 6. 0 counted-but-undrawn signs, so the counting is now honest. - **Single event-distance rule:** FishEventDistance.Within (flat XZ, inclusive) is the only definition, used by the scheduler, F7, legibility and FishSurfaceFx (slot F + f-artist #23).
- **F5 stuck (sim timer, #24, brief F18):** drawable V1/V2 stuck 0.13 / 2.00 / 2.07 s and escape 0.13 / 0.07 / 2.33 s at seeds 101/202/303, under the 5 s bar; V3 (gizzard shad, reported only) stuck 7.13 / 2.00 / 9.73 s, escape 0.60 / 0.27 / 10.13 s. 0 rendered box overlaps, 0 slot fallbacks, Fish.Sim median 0.138-0.144 ms (TestResults/fish-f4f5-{101,202,303}.json; slot24-f4f5.xml, F4F5 3/3 PASS).
- **Web build size (F9):** Web.data.unityweb is 60,263,328 B in the #26 build (Builds/Web/Build, hashes in TestResults/fish-qa/builds/build-hashes.txt) vs 59,855,830 B for the water pod's build of record (TestResults/water-w4/builds/web-size-compressed.txt, 2026-10-06). - **F9 Windows FPS (#26 release build, RTX 4060 Ti / i9-14900K, 1080p windowed, vsync off, 2,613 m shore route, wildlife + birds on):** PASS. Fish on: median 5.76 ms (173.6 FPS), p99 9.96 ms, 99.97% of frames >= 60 FPS, 127 live fish. Fish off: median 5.93 ms, p99 9.99 ms, 100% >= 60. The on-off difference (-0.17 ms median) is run-to-run noise: no measurable fish cost, consistent with Fish.Sim ~0.14 ms in the Editor (TestResults/fish-qa/f9/f9-windows-grade.txt). Two caveats: (a) the walk's fishDrawnMax reads 0 by construction (BellsBendFpsWalk.CountFish samples DrawModes before FishRenderer.LateUpdate, the same frame-order trap as the old F7 counter), so this run doesn't itself prove bodies were drawn. It's not explained; the likely candidates are first-use compilation of the fish/ring shader variants or a burst of cell plans at spawn. Follow-up: warm the fish shaders (ShaderVariantCollection) and log Fish.Sim per frame around the spike.
- **F8 probe (what a player actually saw):** Noah's shore walk had 11 body sightings by the F7 definition in 206 s (3.2/min), vs the automated 7.3-15.0/min; Noah reported seeing one fish. The bluff look drew 0 fish and 1 sign in view, 0 legible. The drawn bodies are dim, brief and murky enough that a player doesn't notice most of them, and no sign was legible on either walk. Fishing will need a much stronger readability channel (surface disturbance, line and lure feedback) than the ambient presentation provides.
