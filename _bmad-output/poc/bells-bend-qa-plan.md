# QA test plan: Bells Bend land and north boundary

Written before testing. Every row is checked by a command qa runs itself with the Editor baton held (or headless where noted). Numbers reported by other agents are recorded as "claimed" and only count once qa has reproduced them. All expected values are computed from `MapConfig` at test time (greenlight condition 7), never typed in.

## Ground rules

- **Baton:** ask `producer-2` for it; before any eval confirm `Application.isBatchMode == false` and `EditorApplication.isPlaying == false`. Release it when done.
- **Independent geo maths:** qa converts lat/lon to UTM 16N with its own script (`scratchpad/qa_geo.py`, standard Krüger series, numpy only). It does not import `tools/terrain/`. Unity position = ((E, N) − centroid) × `MapConfig` horizontal scale. Before any check depends on it, the converter is cross-checked against one known control point.
- **Height maths:** expected Unity Y = (DEM − datum) × `MapConfig.verticalScale` (+ any terrain base offset that `MapConfig` declares). `WaterLevelY` is read from `MapConfig`.
- **Snapshot binding:** each result names the state it was taken against: the `git status` short hash list plus the SHA-256 of `MapConfig.asset`, the terrain `.asset` files and `World.unity` at the time of the check.
- **Windows only.** R3 is N/A (struck by greenlight condition 5).

## Verdict rule

- **PASS:** every L, B and R row passes (R3 N/A), every greenlight condition is met, no AF is triggered, and there are 0 assists.
- **PASS WITH ASSISTS (n):** as for PASS, with 1 ≤ n ≤ 3 assists.
- **FAIL:** any AF triggered, any row failing at the end of the pod, or a greenlight condition broken. This includes a vertical scale outside 0.6–0.85 without a director ruling, bluffs ≤ 40°, or bottoms < 1.5 m above water.
